# 银行资源替换与全球 BIN 目录解决方案

日期：2026-10-27。状态：方案已形成，尚未实施。

依据：[银行资源补充溯源](bank-provenance-search.md)、[逐版本比对证据](../artifacts/bank-provenance-search/bankcardinfo-comparison.json)、[开放目录核验](../artifacts/bank-provenance-search/open-catalogs.json)。本方案承接目录收口计划中的 N03 银行资源问题，并明确全球银行目录的扩展路径。

## 1. 目标与选定路线

采用“历史格式规则替换 + 可选全球 BIN 目录”两条路径，分别验收。

| 编号 | 工作项 | 交付结果 |
|---|---|---|
| B01 | 固定来源与转换证据 | 原始输入、许可声明、署名、版本、转换工具和差异清单 |
| B02 | 替换内嵌银行卡规则 | 保留现有八家银行调用能力，生成来源规则约束下、具有 Luhn 校验位的模拟卡号 |
| B03 | 接入全球 BIN 目录 | 独立离线 SQLite 数据包，提供精确前缀查询、筛选和确定性抽样 |
| B04 | 兼容、重放及交付验收 | 双目标回归、数据身份更新、包消费、恢复及资源释放证据 |

历史规则使用固定 `bankcardinfo@2.0.4`。该版本早于本库引入银行资源，已完成逐条比较；后续版本在这八家银行上的重合情况没有改善，因此本轮不无理由切换来源。

全球目录使用固定 `Techbuddie-Solutions/binlist-data@fcc907c81cf02b12e396b0c12a8c16472b47619a`。它提供 BIN 与发卡机构等来源字段，缺少完整卡号长度；新目录的定位为查询和抽样，不据此补造完整银行卡规则。

两条路径均保持 `netstandard2.0;net10.0`、离线运行、已有资源预算与上下文所有权契约。核心包仍不依赖 SQLite；全球目录放入现有 Catalogs 包及独立数据包，不新增第八个代码包。

## 2. 来源与许可材料

### 2.1 历史银行卡规则

固定输入：

- [npm 发布归档](https://registry.npmjs.org/bankcardinfo/-/bankcardinfo-2.0.4.tgz)。归档 SHA-256 与此前研究证据核对。
- 对应代码提交：[`f0393148c98247348b515ece601939de51f12b23`](https://github.com/navyxie/bankcardinfo/tree/f0393148c98247348b515ece601939de51f12b23)。
- 保留归档中的 `index.js`、`package.json`、README，以及作者和 `license: ISC` 声明。实际输入保存于 `tools/data/bankcardinfo-2.0.4/`。
- 原归档没有独立 LICENSE 文件，台账如实记录；署名材料保留作者 navyxie，不编造版权年份或声称找到上游未提供的许可证文件。分发材料包含许可声明、ISC 条款和转换说明，并明确各自出处。

本轮采用方式是从固定、声明 ISC 的发布物显式重建资源。来源说明写为“基于 bankcardinfo 2.0.4 的历史格式规则”，不把旧资源的高重合度写成直接复制关系的证明。更早的“2013 年银行卡集”没有原始文件出处，保留这一来源边界，不将它描述为当前有效发卡目录。

完成直接来源固定、许可通知、可重复转换和行为验收后，可按“完成合格替换”关闭旧资源任务；不要求无限恢复旧文件的所有历史传播链条。

### 2.2 全球 BIN 数据

固定 [Techbuddie 数据快照](https://github.com/Techbuddie-Solutions/binlist-data/tree/fcc907c81cf02b12e396b0c12a8c16472b47619a)，保存 `bins.csv`、README、LICENSE、`summary.json`、`conflicts.csv` 和转换出处。

其 [CC BY 4.0 许可](https://github.com/Techbuddie-Solutions/binlist-data/blob/fcc907c81cf02b12e396b0c12a8c16472b47619a/LICENSE) 与来源署名随数据包分发；保留合并目录及两个上游的署名与固定版本，明确本项目做过字段规范化、格式转换等修改。数据许可与代码包自身的许可分别列示。

研究时读取到 458,051 条记录，其中国家 CN 为 18,389 条。实施时从固定输入重新验证计数，不以研究数字代替导入成功证据。

## 3. 内嵌规则转换与差异处理

### 3.1 转换规则

新增独立的静态转换工具，例如 `tools/ImportLegacyBanks.py`。工具只读取声明的银行块与规则，不执行下载的 JavaScript，也不安装或运行 npm 包及其依赖。

1. 仅提取原有八家银行，保留来源中的银行英文别名与完整名称；其他银行记录明确统计为“本轮覆盖之外”。
2. 支持已经核实的数字前缀、前缀选择与定长/有限长度区间语法；未识别的目标银行规则必须报错并指出来源位置，不能静默跳过。
3. 源后缀长度映射到现有 `CardRuleItem.Length`，其中包含最终校验位；完整卡号长度等于前缀长度加该字段。
4. 完整规则键采用 `(银行来源别名, 前缀, 后缀长度, 卡类型)`。完全相同的规则去重，保留首次出现顺序和重复记录位置。
5. 当前候选内部没有同银行、同前缀、同长度而类型不同的规则。转换器独立使用完整键，不依赖 `BankInfo.AddRule` 的简化去重；本轮无需修改该公开方法。若固定输入出现预期外的跨类型冲突，转换失败并输出位置，先核对输入和解析，不能 first-wins 或混合旧新规则消除差异。
6. 保留来源规则的长度，包括历史格式中与常见 16/19 位不同的长度；记录完整长度分布。不以通用卡组织长度推断覆盖、补齐或裁剪来源规则。
7. 输出 `Banks.json`、资源 manifest、来源位置映射、重复清单、类型变化清单及旧新差异。输出按固定银行顺序、来源规则顺序生成，字符编码和序列化格式固定。

已保存证据表明，八家银行的来源规则展开后为 855 条，去除 10 条重复后为 845 条完整键；与旧表重合 778 条，新增 67 条（工商银行 28、招商银行 39），移除 54 条，净增 13 条。完整卡号长度范围为 15–19 位。这些数字是实施预期，仍须以固定输入转换验收确认。

54 条旧规则差集均来自招商银行：39 条为类型差异，15 条为本库额外的后缀 11 位规则。39 条类型变化成对出现在新旧集合之间，不是新候选内部冲突。

### 3.2 明确的差异决策

| 情况 | 处理方式 | 向使用者说明 |
|---|---|---|
| 778 条一致规则 | 按新来源重新生成 | 来源身份改变，规则本身重合 |
| 招商银行 39 条类型差异 | 采用所选来源的 CC 映射，旧 SCC 项进入变更清单 | 这是替换来源后的行为调整，不宣称已证明旧表错误 |
| 招商银行 15 条额外长度规则 | 不带入新资源，逐条记录移除 | 不混入尚未取得独立依据的旧规则 |
| 新来源多出的规则 | 经语法、长度、类型和来源位置核对后纳入 | 覆盖允许增加，不强求复刻旧表 |
| 完整键重复 | 去重并计数 | 不将重复条目变成隐含抽样权重 |
| 固定候选内部出现预期外跨类型冲突 | 导入失败，输出位置并核对输入及解析 | 当前已核对候选不存在此情况 |

导入报告必须满足输入、去重、覆盖外记录、保留记录之间的计数闭合，并验证“旧集合差集 + 交集”和“新集合差集 + 交集”分别还原旧新集合。

| 102 | ICBC | 工商银行 |
| 103 | ABC | 农业银行 |
| 104 | BOC | 中国银行 |

## 4. 生成入口与兼容

保留 `IBankCardRandomizer.Generate()` 和原工厂入口，继续返回字符串。旧 `BankCardFieldOptions` 的已有调用方式可用。

为统一上下文补充一个最小入口，拟定契约为：

```csharp
// bankCode 使用上述 bing-legacy 代码；未指定时在有可用规则的银行间抽样。
string FinanceData.BankCard(string bankCode = null, CardType? cardType = null);
```

该方法使用当前 `MockContext` 的随机状态、取消令牌、文本预算和重放身份，不另建随机数生成器。批量与惰性消费复用 `context.Generator(c => c.Finance.BankCard(...))`。

共同生成逻辑为：按条件选银行 → 选规则 → 生成剩余正文数字 → 计算 Luhn 校验位。保留“先银行、后规则”的抽样语义；类型筛选时先排除没有该类型规则的银行，避免随机失败。共享内部算法，不共享可变随机状态。

参数非法时抛参数异常；银行或类型组合没有覆盖时明确失败，异常携带查询条件和数据版本。正常生成保证数字、所选来源前缀/长度与 Luhn，不承诺账户已分配、可支付、真实开户或号码唯一。所选规则的类型是来源声明，不扩展成对任意号码的唯一分类服务。

原生成器和上下文入口各自保证其契约内的确定性，不承诺两者同 Seed 必须输出同一序列。字段路径隔离、重复枚举、单条重放和串并行一致性由上下文入口验收。

## 5. 全球 BIN 目录

### 5.1 数据模型与导入

生成 `bank-bins.sqlite3`，数据集身份为 `bank-bins-techbuddie`，版本包含源提交和 `import-v1`。复用现有目录文件格式、`DataSetInfo` 与 `CatalogSet` 版本集合。

每行 `Kind=bank-bin`，稳定键为 `bin|原始前缀`，保留前导零。输入重复键必须核对：完全重复可合并并计数，字段冲突不能任意覆盖。`Name` 对应来源 issuer；缺失名称保留为空值语义，不编造银行名称。

Payload 保留 `bin`、`brand`、`type`、`category`、`issuer`、机构联系方式、国家字段及 `source`、`seen`。来源空白统一按文档约定表示，保留哪些字段未知。`seen` 是来源快照标记，不解释为发卡机构核验日期。不得凭国家坐标或名称族推导银行总部与分行关系。

采用流式 CSV 解析与事务写入；校验键、列结构、国家字段、行数和来源计数。生成暂存文件，完整验证后再替换目标文件。取消、输入错误或磁盘写入失败应清理本次暂存产物，保留原目录。

### 5.2 查询与易用性

挂载方式继续使用 `UseCatalogFile("bank-bins", path)`。通用调用通过 `context.Catalog("bank-bins")` 提供按键查询、国家/名称/前缀筛选及确定性抽样。

Catalogs 包增加轻量类型适配器，将 `PayloadJson` 转为只读 `BankBinRecord`，提供以下行为；具体签名在实施计划中与现有 API 命名统一：

- 精确查找来源 BIN：只接收目录前缀；不存在时明确返回未命中，不接收完整卡号并暗中截断。
- 按国家、发卡行名称前缀和 BIN 前缀分页枚举；沿用现有 `CatalogQuery` 的索引字段，不新增全表常驻缓存。
- 使用传入上下文随机位抽样一条记录；无筛选覆盖时返回现有 `CatalogCoverageException`。
- 返回数据集版本和覆盖说明，允许用户判断未知字段。

发行方名称前缀筛选只表示文本筛选，不代表已建立统一银行实体。首版不新增任意 SQL 条件、完整 PAN 识别或全局银行实体去重系统。

### 5.3 资源与覆盖

保持每文件一个受同步保护的只读连接、关闭连接池；沿用八文件、每文件 512 MiB、8 MiB 页面缓存配置及有界分页。导入后检查实际文件大小，不能为容纳数据静默提高预算。

路径挂载由上下文拥有，传入实例默认借用；适配器不额外打开连接。活动任务固定使用挂载快照，更新目录通过新文件和新上下文进行。取消、异常、提前结束枚举后释放读取器；上下文释放幂等，释放后调用失败，拥有的文件句柄可关闭。

该来源主要提供六位 BIN，含少量较短旧前缀，未覆盖八位 BIN。未知国家、issuer、类型等信息按原始覆盖保留。目录不含 PAN 总长度，不能给卡号生成入口补齐缺失规则；`category=PREPAID` 不自动覆盖本库卡类型语义。

## 6. 重放、分发与迁移

内嵌数据替换后更新内置数据身份。由于规则集合、类型和生成覆盖改变，同时更新生成契约身份；当前分别为 `china-2025-12-31-domain-v4`、`domain-v5`，实施时选用未占用的新身份。旧重放明确报不兼容，并给出旧新身份，不用新数据静默执行旧重放。

全球目录的源提交、转换版本及数据身份进入现有挂载目录版本集合。精确抽样顺序固定；来源版本不同应拒绝按旧重放恢复。银行名称语言保留来源，不随展示地区猜测翻译。

内嵌规则及必要通知随核心包分发；全球 SQLite、来源许可和 manifest 进入独立版本化离线数据包。复用 `build/pack-data.ps1`、`build/restore-data.ps1`、`MOCKDATA_DATA_ROOT` 和现有 CI 证据路径。数据清单变化产生新的数据包身份，旧清单不回写为新结果。

迁移说明包含：数字银行码的兼容含义、旧新规则计数、39 条类型变化、15 条长度移除、来源边界、固定 Seed 序列变化，以及新上下文入口和可选目录挂载示例。IBAN/BBAN 已完成的替换证据复用，不混入此次银行规则变更。

## 7. 实施顺序与验收

| 阶段 | 实施内容 | 必须验证 |
|---|---|---|
| B01 | 固定输入、许可与转换工具 | 输入身份；八银行映射；目标规则无静默遗漏；重复、类型变化、差集和计数闭合；重新转换结果一致 |
| B02 | 替换资源、统一生成逻辑和上下文入口 | 每条保留规则均生成并核对前缀/长度/Luhn；类型筛选；覆盖异常；39 组类型迁移回归 |
| B03 | 全球导入、类型适配和挂载 | 全量主键及行数；未知字段；来源字段保真；有界查询与抽样；无覆盖；取消与失败清理 |
| B04 | 重放、资源、包消费和交付 | 新身份确定性；旧重放拒绝；借用/拥有与提前终止；双目标 DLL/XML、七包消费、SQLite 原生访问和数据包干净恢复 |

规则矩阵固定 Seed=39、参考时间 `2026-10-27T00:00:00Z`、每条规则记录序号 0–19。两套资产逐条核对，逐条释放，不保存全部输出。上下文生成另验证字段隔离、重复枚举、单条恢复及串行/并发度 4 一致性。

查询与导入测试重点覆盖：短前缀、前导零、缺失国家/机构、字符串转义、CSV 引号换行、重复键冲突、超预算、取消和文件句柄释放。目录记录匹配必须依据完整稳定键，不把发行方名称族初筛的 2,122 条当作已核实银行映射。

先精准测试，再运行受影响核心与 Catalogs 项目；公共 API 和包边界收口时运行一次完整 Release 双资产测试与隔离消费。既有 Schema、行业目录和百万条工作负载按源码影响复用证据；仅新增或实际改变的银行热点先做万条诊断，必要的百万条流式验收正式执行一次，记录吞吐、分配、峰值内存、实际并行度和排队量，不设新硬阈值。

远程 Windows/Linux 必须记录同一代码候选和新数据包的实际运行结果。本地准备完成不记作远程通过。Git 提交、推送、历史重写、数据上传、包版本提升和发布沿用此前单独的授权范围。
