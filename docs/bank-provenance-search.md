# 银行资源补充溯源

核对日期：2026-10-27。范围为资源来源调查；本轮没有替换 `Banks.json` 或修改生成器。

## 结论

找到比此前候选更接近旧数据的来源：`navyxie/bankcardinfo`。固定 npm 版本 `2.0.4` 与本库 832 条规则精确重合 778 条（93.51%），七家银行的全部旧规则均能找到，五家连规则顺序都一致。它可以作为历史格式规则替换的优先候选，但这些相似性不能证明本项目直接从该仓库复制。

同时找到具有明确数据许可证的全球 BIN 目录 `Techbuddie-Solutions/binlist-data`，适合新增发卡行与前缀查询；它没有完整卡号长度，不能独立承担当前卡号生成器的全部契约。银联也提供官方卡表获取渠道，但本轮未取得可随开源包再分发的官方快照及条件。

## 1. 历史规则的高重合来源

固定取证对象：

- [navyxie/bankcardinfo 2.0.4 对应代码](https://github.com/navyxie/bankcardinfo/tree/f0393148c98247348b515ece601939de51f12b23)，提交 `f0393148c98247348b515ece601939de51f12b23`。
- [npm 发布归档](https://registry.npmjs.org/bankcardinfo/-/bankcardinfo-2.0.4.tgz)，registry 记录发布时间为 `2018-04-20T11:29:29.785Z`，早于本项目银行资源引入日期 `2018-12-21`。
- [许可声明](https://github.com/navyxie/bankcardinfo/blob/f0393148c98247348b515ece601939de51f12b23/package.json)：`license: ISC`，作者 navyxie。所查 0.0.4、2.0.4、2.0.6 归档均如此，但没有独立 LICENSE 文件。
- [上游说明](https://github.com/navyxie/bankcardinfo/blob/f0393148c98247348b515ece601939de51f12b23/README.md)：内置规则基于 2013 年国内银行卡集，并有规则未命中时的 Alipay API 回退。说明没有标明该银行卡集原始发布文件，也不能据此断定全部内置规则由 Alipay 抓取。

静态解析 JavaScript 中的前缀与固定/区间后缀长度，不执行 JavaScript，也不调用银行卡号验证接口。比较键为银行别名、前缀、后缀位数、卡类型；本库 `Length` 包含最终校验位，并非完整卡号长度。

| 银行 | 本库规则 | 2.0.4 精确重合 | 原始顺序也相同 |
|---|---:|---:|---|
| 邮政储蓄 | 31 | 31 | 是 |
| 工商银行 | 353 | 353 | 否 |
| 农业银行 | 60 | 60 | 是 |
| 中国银行 | 145 | 145 | 是 |
| 建设银行 | 80 | 80 | 是 |
| 交通银行 | 41 | 41 | 否 |
| 招商银行 | 72 | 18 | 否 |
| 民生银行 | 50 | 50 | 是 |
| 合计 | 832 | 778 | 五家 |

剩余 54 条均为招商银行差异：39 条前缀与长度相同，但本库标为准贷记卡、来源标为信用卡；另 15 条是本库额外的后缀 11 位规则。这是需要核对的差异，尚不能只凭一个社区来源判定哪方正确。来源也含旧表没有的规则及重复条目，不能只把 778 条一致理解为整体可无差别覆盖。

更早的 `0.0.4`（2015-04-20）重合 777 条；`2.0.6`（2020-05-25）重合 778 条。另一个 [2018-03-27 的 Gist](https://gist.github.com/yanweijia/7fea45eab57a0ff355d71546411b004a/454630beb448e74bd5431ec53b1ddbe532af2a22) 同样重合 778 条，但未发现许可声明，因此它主要用于交叉印证这组规则当时已流传。

判断：ISC 是已经核实的包许可声明，不能把该候选描述成“完全没有许可”。未解决的是更早的银行卡集出处，以及本项目的直接引入链条。可以把未来的显式替换记录为“取自固定 bankcardinfo 版本”，不能倒写成“旧 Banks.json 已证实源于 bankcardinfo”。它适合作为历史格式 Mock 规则，不能宣称实时发卡分配。

证据：[逐版本规则差异](../artifacts/bank-provenance-search/bankcardinfo-comparison.json)、[Gist 比较](../artifacts/bank-provenance-search/historical-gist-comparison.json)。包括归档 SHA-256、发布时间、文件清单、逐银行计数和差异。

## 2. 全球开放目录

优先候选为 [Techbuddie-Solutions/binlist-data](https://github.com/Techbuddie-Solutions/binlist-data/tree/fcc907c81cf02b12e396b0c12a8c16472b47619a)，固定提交 `fcc907c81cf02b12e396b0c12a8c16472b47619a`（2026-09-03）。[README](https://github.com/Techbuddie-Solutions/binlist-data/blob/fcc907c81cf02b12e396b0c12a8c16472b47619a/README.md) 明确将 CC BY 4.0 用于合并数据集，[LICENSE](https://github.com/Techbuddie-Solutions/binlist-data/blob/fcc907c81cf02b12e396b0c12a8c16472b47619a/LICENSE) 提供许可正文。其两个声明上游也有 CC BY 4.0 许可；所查材料未发现额外禁止使用条件。

| 候选 | 固定版本/提交 | 已核对结果 | 对本项目的用途 |
|---|---|---|---|
| Techbuddie-Solutions/binlist-data | `fcc907c…` | 458,051 条，国家 CN 18,389 条；有来源标签和冲突记录 | 优先作为独立全球 BIN/发卡行目录 |
| iannuttall/binlist-data | `e90a68a7baee2bfc84c9d07a71096ceac43e9e2d` | 343,063 条；CC BY 4.0，2020 年归档 | 已被上述合并目录吸收 |
| venelinkochev/bin-list-data | `023a4f68ab1b5d7edd45f03acb132f88a49db96a` | CC BY 4.0；含前缀、品牌、类型、发卡行和国家 | 合并目录的另一上游 |
| binlist/data | `7400e175f00daaf64f239101fc382f988c20d46e` | 5,805 条；未找到许可声明；匹配目标银行的 6 条均无卡号长度 | 当前不选为替换来源 |

合并目录以六位 BIN 为主，保留少量较短旧前缀，不覆盖八位 BIN；它是社区目录，非官方完整登记册。八家银行的英文名称族初筛得到 2,122 条，但其中含分行及卡产品标签，这不是已确认的逐条银行归属。它没有完整卡号长度，`category=PREPAID` 也不能不加解释就映射本库全部预付费卡规则。

采用时应保留来源、署名、许可证和转换说明；目录覆盖不足与再分发许可属于不同问题，不因缺少全部 832 条旧规则而否定这个数据源。

证据：[开放目录核验](../artifacts/bank-provenance-search/open-catalogs.json)，包含固定链接、全量计数、字段说明、覆盖初筛和限制。

## 3. 官方卡表及银行代码

[银联官方 FAQ](https://pcs.unionpay.com/ycb/pcweb/NEWbzzx/cjwt/YYFW/ywzx/ywzc/art/2023/art_48ea26fd6f6b4d568a34aba05c2e0e68.html) 明确给出每月卡表的获取位置：一窗办 → 帮助中心 → 文档资源 → 其他资料 → 卡表信息。文件解释对应其交换系统技术规范的文件接口部分。该页面证明存在官方渠道；没有在已读页面中找到可随开源项目公开再分发的授权，不能据此把官方卡表加入数据包。本轮也没有确认文档资源页面是否要求登录。

旧 `Code=100/102/...` 与社区数据的 `PSBC/ICBC/...` 不是同一命名空间。数字代码可以保留为本库历史兼容标识，明确为 `legacy`；只有对外声明为某种官方标准时才必须补该标准的依据。缺少旧数字代码本身不应阻止采用新数据源。

## 4. 建议的收口路径

1. 将固定 `bankcardinfo` 列为旧格式规则的首选替换候选，保存发布归档、ISC 声明与署名，静态转换并报告增加、删除及类型变化。上游历史年份和准确性边界需明示；不能将重合推断升级成已证实的原始来源。
2. 全球 BIN 目录单独采用明确 CC BY 4.0 的候选，扩展前缀、发卡行、卡组织、国家和来源查询；缺少 PAN 长度的记录不自动生成真实银行格式卡号。
3. 若要求官方、当前有效的银行关联，则通过银联渠道取得对应快照和适用分发条件。这比继续从匿名转载文件反推权利和实时性更直接。
4. 当前只完成研究，不据此将 N03 标记为完成。原资源尚未替换，直接来源仍未被证明；后续可以通过有记录的替换关闭历史资源问题，无需无限追索旧表的每一条记录。

本轮验证为静态数据解析、规则比较和许可/来源文件核对，没有运行无关的完整测试，也没有发送外部消息。
